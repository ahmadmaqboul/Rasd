# visual_style — الأسلوب البصري

**الهدف:** دليل بصري (visual style guide) يصف كيف يبدو محتوى الحساب، وما الذي يرتبط منه بالأداء — بحيث يستطيع مصمّم أو مصوّر تطبيقه.

## البيانات

`node bin/rasd.mjs study data <id> --module visual_style` ← ملفات `data/posts-*.json`.
الصور: لكل منشور حقل `images` بمسارات نسبية داخل الحزمة. **المسار الكامل = `packageDir` + `/` + المسار.**

**افتح كل صورة بأداة Read.** لا تحكم على صورة لم ترها، ولا تستنتج الشكل من النص المرافق.
للفيديو: الحزمة تحوي لقطات مفتاحية أو ورقة تماس (contact sheet) — تعامل معها كتسلسل زمني.

## ماذا تسجّل لكل صورة

| البعد | القيم |
|---|---|
| الخلفية | لون سادة / تدرّج / استوديو / مكان حقيقي / تصميم جرافيكي |
| الألوان | 2–4 ألوان غالبة بالاسم (وبالـ hex التقريبي إن كان واضحاً) |
| الإضاءة | ناعمة / قاسية / طبيعية / غير منطبق (تصميم مسطّح) |
| التكوين | منتج في الوسط / شبكة منتجات / نص هو البطل / لقطة قريبة |
| المحتوى | منتج فقط / منتج مع يد أو شخص / شخص فقط / نص فقط |
| المصدر | استوديو / UGC (تصوير عفوي) / تصميم جرافيكي / مولَّد بالذكاء الاصطناعي (فقط إن وُجدت علامات واضحة) |
| النص على الصورة | لا يوجد / قليل (حتى 5 كلمات) / متوسط / كثيف — وما هو: سعر؟ عرض؟ ميزة؟ |
| وضوح الرسالة | هل يُفهم المنتج والعرض خلال ثانية واحدة؟ نعم / جزئياً / لا |

للفيديو أضف: طول المقطع، سرعة التقطيع، أول 3 ثوانٍ (الافتتاحية البصرية)، وجود صوت/ترجمة على الشاشة إن ظهر.

## طريقة الحكم

1. **الاتساق:** هل للحساب هوية بصرية واحدة (ألوان، خط، قالب) أم كل منشور بأسلوب؟
2. **الربط بالأداء:** قارن الأبعاد أعلاه بالتفاعل (`likes + comments`). أي اختيار بصري يظهر في الأقوى ويغيب عن الأضعف؟ اذكره كارتباط لا كسبب مؤكّد.
3. **القابل للنسخ:** ما الذي يستطيع متجر آخر تطبيقه غداً؟

## حدود الثقة

أقل من 10 صور: `low` لأي ربط بالأداء، و `medium` كحد أقصى لوصف الأسلوب نفسه. اذكر عدد الصور التي فحصتها فعلاً في `why`.

## النتائج المطلوبة

| `key` | المحتوى |
|---|---|
| `style-guide` | **إلزامية.** وصف الأسلوب العام للحساب |
| `visual-performance` | علاقة الاختيارات البصرية بالتفاعل (إن ظهرت) |
| `consistency` | مدى اتساق الهوية البصرية |
| `opportunity-<اسم>` | حتى 2: ثغرة أو فرصة بصرية واضحة |

`data` لنتيجة `style-guide` — هذا ما يرسمه التطبيق كدليل بصري ولوحة مزاج:

```json
{
  "palette": [{"name": "أسود", "hex": "#0b0b0b"}, {"name": "أصفر", "hex": "#ffd400"}],
  "backgrounds": ["لون سادة", "تصميم جرافيكي"],
  "lighting": "غير منطبق (تصاميم مسطّحة)",
  "composition": ["نص هو البطل", "منتج في الوسط"],
  "subjects": "منتج فقط",
  "source": "تصميم جرافيكي",
  "textOverlay": "متوسط",
  "do": ["جملة قابلة للتنفيذ"],
  "dont": ["جملة قابلة للتنفيذ"],
  "moodboard": ["post:ig:XXXX", "post:ig:YYYY"],
  "imagesReviewed": 5
}
```

`moodboard`: 4–9 معرّفات تمثّل الأسلوب (من `evidence` الحزمة فقط).

## الدراسات الكبيرة والاستئناف

- افتح صور ملف واحد (20 منشوراً) في كل مرور، وسجّل الأبعاد في جدول ملاحظات قبل الانتقال.
- في الوضع «سريع» الحزمة تحوي عيّنة صور فقط: اذكر في `why` أن الحكم على عيّنة.
- `style-guide` تُكتب بعد آخر ملف. عند الاستئناف: إن وُجدت في `existingFindings` فحدّثها بنفس المفتاح بدل إنشاء أخرى.

## الأسلوب

- صف ما تراه بكلمات يفهمها غير المصمّم: «خلفية سوداء ونص أصفر كبير» لا «تباين لوني عالٍ».
- `do` / `dont`: تعليمات تنفيذية قصيرة، كل واحدة مبنية على دليل.
- لا تحكم على الذوق («جميل/قبيح»)؛ احكم على الوضوح والاتساق والأداء.
